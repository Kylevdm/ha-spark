Problem

The gate-read-write-verify-classify ladder is copied eight times, with two separate bounded read-back loops beneath it (_verify_read_back :934, _read_back_option :982); every recent fix (#144, #148, #150, #151) edited several copies, and the fog's write-endurance backoff has nowhere to keep per-register state.

Solution

One verified-write module owns the ladder and the outcome vocabulary; the register bank (block, current, select, work-mode bit) sits behind an internal seam with two adapters, the HA overlay and an in-memory bank the three Solis test files share.

Wins

  • locality: backoff lands in one place
  • interface shrinks: 8 ladders → 1
  • tests: one fake bank, not 8 fakes
  • register map owned once, not 3×
  • secret-free errors (#151) enforced once

Deletion test: delete the ladder and it reappears at all eight sites — it earns its keep, but is spread rather than concentrated. 100 driver tests already cross the public interface (apply, reconcile_holds, write_safe_state) with zero private calls, so they survive the deepening unchanged.

Problem

Every tick function takes settings and builds its own client and device (:172, :223, :276, :326, :435, :492, :514, :522, :568, :693), so the loop's only test seam is the module namespace; the ordering rules (#143's reconcile-before-replan, relinquish-once, hot-reload resets) are unreachable from any interface, which is how #147 slipped in.

Solution

Extract the loop body as a tick over an explicit daemon state, with the client and device accepted as dependencies; run_forever keeps servers, sleep and shutdown. Split capability lookup from device construction so no client is opened to ask a pure question.

Wins

  • tests hit one interface: tick(state, now)
  • locality: ordering rules in one body
  • #147 becomes a one-function test
  • delete 8-attr monkeypatch setups
  • one client per tick, not five
ADR-0003 is preserved: the reconcile keeps its own per-minute cadence and stays outside apply. Only the loop's shape changes, not the seam the ADR decided.

Problem

The rule "past every known hold end and still untrusted" is written twice (:453-457 and :685-687); the scheduler imports two private names from the tariff module to fold dispatches into holds; and the fog's untested day-of Flexibility event pickup is untested because the composition has no interface to test.

Solution

One module owns the last-trusted hold set: it is fed every dispatch read and every plan, and answers "which intent may the reconcile act on now" and "may ha-spark relinquish now". The scheduler, shutdown and CLI ask it; nobody else holds the state.

Wins

  • locality: relinquish rule exists once
  • day-of event pickup testable
  • tariff privates stop leaking
  • reconcile_tick loses 3 of 5 params

Vocabulary note: "hold" and "hold trust" carry real decisions (#143 §3–§5) but are not in CONTEXT.md. Naming this module would add the term.

Problem

About 450 of the driver's 1245 lines are export delivery; the driver is the only importer of both export stores and opens the event store five times per apply; ExportIntent is a frozen dataclass with one constructor, yet the driver and scheduler read it by getattr seven times as if it might not exist. A second export-capable adapter would copy private methods.

Solution

Move validation, the verified-event record and the four operator notices to an export-delivery module at the plan-apply seam; the driver keeps register mechanics and its date-less wall-clock arming rule. The reconcile still never reads export state (ADR-0003).

Wins

  • locality: verify → record → notify in one place
  • driver interface shrinks by ~450 lines
  • fog's "write-only identity" decided once
  • delivery rules tested with a fake device
Seam discipline: only Solis exports today, so the device-side seam is hypothetical until a second adapter (#136 discharge validation, #142 finer holds) arrives. The locality gain — one store, no duck-typing — stands on its own without the seam.

Problem

Solution

One apply-to-device function with the skip as an explicit option; one habit-predictions function replacing both the orchestrator's private gather and the CLI inline copy.

Wins

  • CLI and daemon cannot drift
  • delete ~60 lines of copy

Looked at, left alone

  • Pure clock helpers in the driver (_next_wall_clock_occurrence, _clock_window_open, _export_not_yet_armed): small interface, real depth, tested directly. Deep as they stand.
  • ChargeIntent / ChargePlan construction: exactly one construction site each (planner.py). Trust flags travel as fields, not parameters. No friction.
  • Plan pipeline (plan_run.current_plan): #91 did its job; four callers share one entry. gather_inputs and compute_plan are large but concentrated, each with one caller path.
  • Tariff config validators (four near-identical validate_*_tariff functions): boilerplate, but ten lines each and test-enforced against the add-on schema. Not worth a card.
  • The reconcile seam itself (ADR-0003, #143): the split between apply and reconcile_holds is a real, argued seam. Nothing here reopens it.

Top recommendation

1 · The verified register write

It is the most-touched file in the repo, every fix of the last two weeks edited several of the eight copies, and the fog's next Solis need — backing off writes the inverter keeps rejecting — has no home until this module exists. It moves no seam and changes no caller; the 100 existing driver tests already cross the public interface and would carry the refactor unchanged, which makes it the safest deepening to land before supervised commissioning (#131, #134).

Next after that: card 2 — #147 is an open bug that a tick seam would have caught, and cards 3 and 5 both get cheaper once the loop has one.
