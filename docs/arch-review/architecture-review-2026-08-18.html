Strong

Dashed red callers pass no schedule; the None default silently substitutes the fixed two-rate provider. On a dynamic or octopus_intelligent install, /agent/plan, the MCP tools, and offline ask answers describe a different plan than the one the daemon applies.

After — one deep module

current_plan(settings, rest) → PlanRun
gather_inputs · REST lifecycle
provider selection · build_schedule
compute_plan(…, schedule) — required arg

Six call sites shrink to one line each.

compute_plan's schedule default is deleted — the tariff schedule becomes part of the planner's interface, and the fixed fallback must be requested explicitly.

Problem
Pure planner, pure providers, both deeply tested — the defect lives in the wiring, where nothing tests it. No locality.
Solution
One deep module (energy/plan_run.py) hides REST → inputs → schedule → plan; delete the schedule=None default.
  • Fixes a live plan-divergence bug
  • Leverage: one interface, six call sites
  • Locality: wiring bugs concentrate in one module
  • Unlocks daemon-vs-agent parity test

3 · Move agent-exposure gating from build time to request time

Strong

api/server.py:128-131,269,274 · agent/mcp_server.py:38 · scheduler.py:221 · config.py:392

Before — gate read once, at build

build_app() reads exposure once → routes frozen
hot-reload drifts past the route table
POST /api/config rewrites settings — routes unchanged until restart
agent_surface: off → /agent/* and /mcp still mounted behind ingress

After — one predicate, read per request

allowed(state, tier) → bool
agent_surface == "off" → deny all
exposure matrix (read / read_act / read_write)
reads state.settings at call time

Both adapters — FastAPI dependency and MCP tool guard — call the same predicate. Two adapters: the seam is real.

Problem
The exposure matrix is written twice (HTTP router + MCP) and captured at build time, so hot-reload can't move it; and agent_surface: off — the shipped default, documented as the master switch — gates only the extra published port, not the ingress-mounted /agent/* and /mcp.
Solution
Register routes/tools once; a single allowed(state, tier) predicate reads state.settings per call and folds agent_surface into the same gate.
  • Config's stated interface becomes the implemented one
  • Exposure matrix written once, not twice
  • Hot-reload gate tests become writable
Security-relevant: CLAUDE.md requires every inbound surface be gated alike. Ingress is authenticated, so this is drift, not an open door — but the fix is the safe default.

Drivers read identity and limits straight from Settings, so a second device of the same driver is unrepresentable — two AlphaESS units would share one serial. The dual-read shim isn't a shim any more; it's a second, parallel config path.

Problem
The Device interface (4 members — genuinely deep) is undermined by its constructors reaching past DeviceConfig into flat Settings keys; scheduler.py still keys guard reconfiguration off the flat settings.inverter; and capabilities needs a live REST client to answer a no-I/O question.
Solution
Push per-device knobs into DeviceConfig (typed fields or a params sibling of entities); flat keys feed synthesis only. Trivial adjacent deletions: energy/chargers.py (dead re-export) and both supports_live_rate attrs (superseded by Capability.CHARGE_RATE).
  • Two devices per driver becomes representable
  • Structured devices path finally testable end-to-end
  • Dissolves scheduler's REST-client dance for capabilities
  • Dead-code deletions: Strong, trivial

6 · Carve seams into run_forever — tick + server lifecycle

Worth exploring

energy/scheduler.py:203-289 · tests/test_scheduler.py (six monkeypatched module attrs per test)

Before — four concerns, no seam

ingress + agent-port uvicorn lifecycle
supply-guard capability detection
daily plan trigger + guard tick + signal sampling
tests monkeypatch 6 module attrs to run one loop

After — two named seams

async with api_servers(state, settings): …
async def tick(state, now) → None
run_forever = servers + clock + tick loop

Tests call tick with a real clock value; _FakeDatetime and the fake-server plumbing go away.

Problem
Tests reach past the interface — they know the module's internal names, so renames break them and real wiring changes slip through. The interface is supposed to be the test surface; here there isn't one.
Solution
Extract api_servers (context manager hiding both uvicorn servers and their teardown) and tick(state, now) (one loop iteration, clock passed in).
  • Loop tests stop monkeypatching module internals
  • Server lifecycle testable through one seam
  • Pairs with candidate 4's no-REST capabilities fix

7 · Reservations exist in the domain model, not in the code

Speculative

energy/planner.py:159-190 (ChargePlan) · report.py · publish.py · intent_parser.py · copilot.py

Before — the plan is a bag of ~25 floats

Every consumer — report, publish, intent parser, copilot — must understand every field individually.

After — plan lines trace to reservations

reservations: tuple[Reservation, ...]
(at_time, kwh_target, reason)
"reserve 3 kWh for the 17:00 event"
Problem
CONTEXT.md and ADR-0002 say every plan line must trace to a reservation; grep -i reservation across ha_spark/ returns zero hits. The planner computes a single scalar deficit → target SoC.
Solution
Not a refactor to do now — the thing to design before the next planner feature (flexibility events, V2L budget), since both must be expressed as reservations per ADR-0002. Stays inside merit-order + reservations; no optimizer.
  • Copilot explains from one structure, not 25 fields
  • Natural home for V2L budget + flexibility events
  • Candidates 1–2 get easier once the plan is a richer value
Aligned with ADR-0002, not against it — this implements the reservation mechanism the ADR already committed to.

Top recommendation

1 · Give the plan pipeline a module

It fixes a live bug — agent, MCP, and offline-ask answers diverge from the daemon's plan on any non-fixed tariff — while creating the deep module candidates 2 and 7 want to build on. Deleting compute_plan's schedule=None default turns the whole class of silent-fallback bugs into type errors, and the parity test it unlocks (daemon plan == agent plan under a dynamic tariff) is exactly the test the codebase can't write today.

Agent vs API note: agent/tools.py behind its two adapters (FastAPI router, MCP) is the best-factored seam in the codebase — two adapters, real seam. The remaining duplication there is the exposure matrix (candidate 3) and the GET /api/plan-serves-cached vs get_plan-recomputes naming collision.
