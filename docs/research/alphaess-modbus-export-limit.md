# Research: AlphaESS local Modbus export-limit readback

Issue: [Research: AlphaESS device export limit over local Modbus](https://github.com/Kylevdm/ha-spark/issues/296).  Date: 2026-10-13.

## Answer

**There is a readable feed-in *percentage*, but the published household Modbus map does not establish a verifiable device export bound for scheduled battery dispatch.** The AlphaESS *Register Parameter List* defines holding register `0x0800` as `MAX Feed into grid percent`, `R/W`, unsigned 16-bit, `1%/bit`. It also lists `0x0801–0x0802` as “PV Capacity Storage” and `0x0803–0x0804` as “PV Capacity of Grid Inverter,” both 32-bit watts. A separate `0x0700` “Feed into grid percent” is in the document's **HHE MEC only** section, so it is not the household SMILE register. [Vendor register list, pp. 18, 24 (archived copy)](https://github.com/ramonvanraaij/ha-alphaess-modbus/blob/fdac291/docs/alphaess_modbus_register_parameter_list.pdf#page=24).

The published household map labels no enable/status register for that limit. AlphaESS's current portal documentation says some three-phase models have a *master switch* for maximum feed/take-off power control, and that available settings vary by model. A read of `0x0800` therefore proves the configured percentage is readable, **not** that the limit is enabled. [AlphaESS Device Advanced Settings, “Feed/Buy power”](https://docs.alphaess.com/portals/portal-home-owners/settings/device-advanced-settings.html#feedbuy-power); [vendor register list, p. 24](https://github.com/ramonvanraaij/ha-alphaess-modbus/blob/fdac291/docs/alphaess_modbus_register_parameter_list.pdf#page=24).

The percentage's watt denominator is also uncertain for this Modbus map. AlphaESS's current UI documents a coefficient against *rated inverter power* for residential settings, while its C&I manual says *installed PV power*. The vendor register list gives PV-capacity registers but does not say which quantity `0x0800` multiplies. The [senalse integration maps `0x0800` as a percent](https://github.com/senalse/ha-alphaess-modbus/blob/3b944d6/custom_components/alphaess_modbus/const.py#L678-L690), but its code description says inverter AC capacity, while its [README calls it installed PV capacity](https://github.com/senalse/ha-alphaess-modbus/blob/3b944d6/README.md). Do not convert the raw percent to an assured watt bound from these documents alone. [AlphaESS residential settings](https://docs.alphaess.com/portals/portal-home-owners/settings/device-advanced-settings.html#feedbuy-power); [AlphaESS C&I export limitation](https://docs.alphaess.com/portals/cni-portal/installation/installation-commissioning.html#export-limitation).

## Does it cover battery discharge?

**In the AlphaESS setting as described for normal operation, yes. For local Modbus dispatch, unresolved and possibly no.** AlphaESS calls the setting a limit on the whole system at the grid connection point and explicitly says the ceiling still applies to its *Feed-in Control* feature that discharges the battery to the grid. Its C&I commissioning manual describes export limitation using the sum of PV generation and battery discharge, and reducing battery discharge when that sum exceeds site load. These are vendor statements about the setting's intended behavior, but do not explicitly test the local `0x0880–0x088A` dispatch interface on household SMILE firmware. [AlphaESS Device Advanced Settings](https://docs.alphaess.com/portals/portal-home-owners/settings/device-advanced-settings.html#feedbuy-power); [AlphaESS C&I commissioning manual, “Export Limitation”](https://docs.alphaess.com/portals/cni-portal/installation/installation-commissioning.html#export-limitation).

The author of the [Hillview AlphaESS Modbus dispatch automations](https://projects.hillviewlodge.ie/alphaess/#dispatch) warns from their implementation that its dispatch automations **do not honor** the configured “Max Feed to Grid” limit. Their warning is directly relevant to ha-spark's planned local dispatch, but it is not a model-by-model firmware test report, so scope remains uncertain. [Hillview dispatch warning](https://projects.hillviewlodge.ie/alphaess/#dispatch). A different [community implementation claims](https://github.com/ramonvanraaij/ha-alphaess-modbus/blob/fdac291/README.md) its mode 23 flow is hardware-capped by `0x0800`, which supports a mode-dependent interpretation rather than a universal dispatch guarantee.

## Consequence for the export gate

The [site export guarding decision](https://github.com/Kylevdm/ha-spark/issues/283#issuecomment-6133231536) requires a read-back of both an *on* switch and a setpoint, and a bound that actually constrains scheduled battery export. The documented local AlphaESS map supplies only a readable percentage setpoint. The status switch, its watt conversion, and dispatch coverage are unproven. **Treat AlphaESS as failing that gate for scheduled battery export on present evidence.** This is an inference from the cited register map, vendor UI docs, and dispatch warning, not a claim that every AlphaESS model lacks such protection.

To reconsider on a particular model/firmware, obtain its vendor register definition (or vendor confirmation) for the enable/status state and watt basis, then observe a controlled local-dispatch battery export with a low installer-set limit while reading the grid-connection meter. Include at least the intended dispatch mode and any alternative mode the implementation may use; the community reports differ by mode. The verification is read-only on the ha-spark side: the owner/installer sets the bound, and ha-spark reads it. [Export guarding decision](https://github.com/Kylevdm/ha-spark/issues/283#issuecomment-6133231536); [AlphaESS setting documentation](https://docs.alphaess.com/portals/portal-home-owners/settings/device-advanced-settings.html#feedbuy-power); [Hillview dispatch warning](https://projects.hillviewlodge.ie/alphaess/#dispatch).

## Source handling

The original `alphaess.de` URL for the *Register Parameter List* returned HTTP 404 on 2026-10-13, so the archived copy bundled in a Modbus integration was used. The PDF identifies itself as AlphaESS's register list; the extracted table on p. 24 was checked directly. The cited AlphaESS Docs pages are live first-party product documentation. The Hillview claim is a firsthand implementation warning and is retained as contrary empirical evidence, not substituted for a vendor guarantee.
